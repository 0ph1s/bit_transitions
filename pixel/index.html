( 03 )Como funciona
01

Um triângulo cobre o viewport

Três vértices (-1,-1) (3,-1) (-1,3) num VBO estático. A hipotenusa x+y=2 nunca corta o quadrado NDC [-1,1]² — a viewport inteira cai dentro do triângulo. O vertex shader só passa a UV [0,1].

02

Uma grade lógica, não DOM

48×28 no desktop, 34×24 no tablet, 24×38 no mobile. São números que vão para o uniform u_grid — nenhum elemento HTML nasce por bloco. O badge "células ativas" é literal: é o produto colunas × linhas da grade em uso.

03

Cada fragmento é uma célula

cell = floor(v_uv × u_grid) e um atraso por célula: a diagonal soma coluna+linha; a radial usa a distância ao centro; o aleatório consulta um hash determinístico pela posição da célula. Zero Math.random().

04

Easing e opacidade sem divisórias

t = (u_progress − delay) / interval, rampa easeOutExpo no shader e saída vec4(u_color, a). Cada fragmento é pintado com alpha — a grade é contígua por construção, sem linhas vazias entre blocos.

05

Cobre → troca → revela

A tela só é considerada coberta quando u_progress = 1 + interval: totalmente preta. Só então o conteúdo muda (history.pushState + rolagem, ou um fetch em páginas reais) e a revelação reutiliza o mesmo shader com progresso decrescente, sem recompilar.

06

Fallback e acessibilidade

WebGL 2 → WebGL 1 → cortina CSS por opacidade. E prefers-reduced-motion corta a animação e troca o conteúdo na hora — a navegação nunca depende do suporte gráfico.

O ciclo da transição
A cobrir progresso 0 → 1
→
B trocar conteúdo entra em swapAt = 1.0
→
C revelar mesmo shader, progresso decrescente

Nada recopila: nos três estágios é o mesmo programa — só u_progress muda de direção.

Decifrando os uniformes
u_grid
colunas × linhas da grade lógica — desktop 48×28
u_progress
o relógio da fase — avança no cover, volta no reveal
u_interval
atraso entre células vizinhas — o "espaço" entre blocos
u_mode
o padrão de varredura: diagonal | radial | aleatório
u_ease
a rampa de entrada de cada bloco (expo | cubic | linear)
u_color
a cor dos blocos — ler do --ink do tema
// fragment — one pixel per frag, drawn in parallel
#version 300 es
precision highp float;
in vec2 v_uv;
uniform vec2  u_grid;
uniform float u_progress, u_interval;
uniform int   u_mode, u_ease;
uniform vec3  u_color;

float hash(vec2 p){ p = fract(p * vec2(234.34, 435.345)); p += dot(p, p + 34.23); return fract(p.x * p.y); }
float easeOutExpo(float t){ return t >= 1.0 ? 1.0 : 1.0 - pow(2.0, -10.0 * t); }

void main() {
  vec2 cell = floor(v_uv * u_grid);         // this fragment's cell
  float delay = (cell.x / u_grid.x + cell.y / u_grid.y) * 0.5; // diagonal (← switch the mode here)
  float t  = clamp((u_progress - delay) / max(u_interval, 1e-5), 0.0, 1.0);
  float a  = easeOutExpo(t);                 // easing in the shader
  outColor = vec4(u_color, a);               // translucent block
}
// engine — everything tweakable at runtime
PixelTransition.CONFIG.grid     = { columns: 64, rows: 36 }; // fixed grid
PixelTransition.CONFIG.duration = 0.95;                       // s per phase
PixelTransition.CONFIG.swapAt   = 1.0;                        // swap only when 100% black
PixelTransition.setMode('radial');                            // 'diagonal' | 'leftright' | ...
PixelTransition.setEasing('expo');                            // 'expo' | 'cubic' | 'linear'
